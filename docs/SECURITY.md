# Security & reliability review — Daymark

Scope: the hackathon demo deployment (public web app + Rust API + AMD-hosted model
endpoint). No accounts, no payments, no personal data. Reviewed Oct 12, 2026.

## Threat model (what could actually go wrong)

| # | Threat | Exposure | Mitigation |
|---|---|---|---|
| 1 | **Secret leakage** (LLM API key, GPU credentials) into the public repo | Credentials usable to burn compute budget | Keys only via env vars; `.gitignore` covers `.env*`; no key material in artifacts/logs; repo has no CI secrets |
| 2 | **Prompt injection** via data → narrative | In our flow the *facts* are numeric and generated by our own engine; the model's output is display copy only. Injected instructions cannot alter figures (they are not in the prompt at all), cannot trigger tools, and any number they introduce **fails grounding** | Grounding checker + single retry + template fallback; the LLM has no tools and no write path |
| 3 | **Fabricated numbers shown to a manager** | Decisions based on invented figures | Structural: narratives verified figure-by-figure against the facts payload; `source` badge shows model vs template |
| 4 | **Ledger tampering** | Audit trail loses credibility | SHA-256 hash chain; verification on every read; tamper-detection covered by tests |
| 5 | **Abuse of the public API** | Cost abuse (LLM calls), resource exhaustion | Demo scope: single-tenant, no PII. Mitigations for a hosted pilot listed below (rate limits, authn) |
| 6 | **SSRF / input validation** | API takes store/date/params only; all validated and clamped (`service_level` 0.5–0.99, scales bounded); no user-supplied URLs are fetched | `parse_date`, clamps in `api.rs` |
| 7 | **SQL injection** | Ledger writes/reads | sqlx parameter binding throughout; no string-built SQL |
| 8 | **Dependency risk** | Supply chain | Mainstream, pinned deps (Axum, sqlx, polars, LightGBM); lockfiles committed; no postinstall scripts in the Rust/engine path |
| 9 | **Model endpoint exposure** | vLLM endpoint reachable publicly | API key required by vLLM (`--api-key`); recommend binding to the backend host or private network; instructions in `infra/amd/README.md` |
| 10 | **Misleading claims** | Judge/reader trust | `docs/PROOF.md` maps every claim to its evidence and labels simulated parts |

## Verified properties (with tests)

- `backend/src/ledger.rs` — chain linkage + tamper detection (test: mutating a row breaks verification).
- `backend/src/grounding.rs` — grounded copy accepted; invented number rejected; thousands/decimal normalization.
- `backend/src/sim.rs` — accounting identity `sales + lost = demand` per policy; determinism; markdown policy never worsens waste vs forecast-only on fixtures.
- `scripts/smoke.sh` — end-to-end: facts → grounded generation → decision → chain → replay deltas.

## Deliberate demo-scope decisions (documented, not accidental)

- **No authentication**: the demo is a read-only public store plus an *append-only*
  decision log with no destructive operations. A pilot adds: OIDC login, per-store
  authorization, rate limiting per token, and an outbound allowlist for the model host.
- **CORS `allow_origin(Any)`**: enables the demo frontend from any host. A pilot pins
  exact origins.
- **No PII, ever**: the source dataset is public and anonymized; nothing user-entered is
  persisted beyond decision metadata (action, item, quantity, reason).

## Operational failure handling

- Model endpoint down → `/api/brief/:store` still returns facts; generation returns a
  clear `upstream` error; the UI keeps the facts view usable and labels failures.
- Artifacts missing → API refuses to start with an actionable message.
- Replay is pure local computation; it cannot fail because a third party is down.
